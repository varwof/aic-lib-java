# Cross-language consistency

AIC is a cross-language protocol. The Java SDK is a faithful port of the Go
reference and is kept byte-compatible with it. Consistency is enforced by
three test classes:

## DER vectors (`DerVectorsTest`)

`DerVectorsTest` compares DER byte output against vectors generated by the Go
implementation. This proves that field order, tags, lengths, INTEGER encodings
and DEFAULT-value omission match Go exactly — a byte-level guarantee that
certificates, DA signatures and JWTs interoperate between languages.

## JWS round-trips (`JwsTest`)

`JwsTest` round-trips every implemented algorithm (ES256, RS256, PS256, PS384,
PS512, EdDSA): sign → verify → re-verify, including RFC 7638 JWK thumbprints
and SPKI key-binding hashes.

## Go conformance (`GoConformanceTest`)

`GoConformanceTest` validates a token **produced and signed by the Go
implementation** through the full 11-step pipeline. This proves the Java
validator accepts Go-signed artifacts end-to-end: signature encoding, SPKI
key-binding hashes and JWK thumbprints all match.

## Porting checklist (used for the C# port)

- Enum names and values (`DelegationMode.AUTHORIZED` etc.).
- OID constants (see `Oids`).
- DER field order & tags (see [cert-profile.md](cert-profile.md)).
- `GeneralizedTime` encoding (seconds precision).
- RSA-PSS salt length = digest.
- JOSE algorithm allowlist & MAY-level exclusions.
